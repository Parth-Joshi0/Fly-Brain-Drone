# StabilizerNeuron

Everything specific to the DNg02 flight-motor circuit that's independent of the shared Brian2 network — the 24-cell population that sets thrust and steering from residual optic flow, replacing what a drone's built-in gyroscope/IMU stabilization would otherwise do, with an actual connectome-derived pathway instead.

The circuit code itself (`fly_brain_controller.py`, `flybrain_controller.py`) stays at `NeuralPathways/` root — it's built as one shared Brian2 `Network` with the escape circuit for measured performance reasons, not something that can be split into a separate file without rewriting the network itself. See `NeuralPathways/README.md` for why. Everything below genuinely is independent of that shared network, though, so it lives here.

## Files

| File | What it does |
|---|---|
| `dng02_circuit_neurons.json` | The 24 DNg02 output neurons and their 120-neuron drive pool, generated by `build_dng02_circuit.py`. Loaded by `../fly_brain_controller.py` at `DNG02_IDS_PATH`. |
| `build_dng02_circuit.py` | One-off generator for `dng02_circuit_neurons.json` — finds the 24 DNg02 cells and their drive pool from the connectome data in `../Data/`. Run under the brian2 env; re-run and re-paste its output if `MAX_DRIVE_RATE` or the drive pool changes. |

```bash
conda run -n brian2 python NeuralPathways/StabilizerNeuron/build_dng02_circuit.py
```

## Tests (`Tests/`)

### `test_dng02_circuit.py`: does the population code work?

The DNg02 counterpart to `NeuralPathways/Tests/test_brain_circuit.py`, and the **gate for everything downstream** — nothing DNg02-related should reach a real drone until this passes. Drives the flight-motor half directly and prints the recruitment ladder, cross-synapses back into the escape circuit, a symmetric drive sweep (recruited cells, `thrust`, `steer`), an asymmetric sweep, and a 2-D `loom × drive` sweep.

```bash
conda run -n brian2 python NeuralPathways/StabilizerNeuron/Tests/test_dng02_circuit.py
```

Ends in hard assertions and a non-zero exit on failure: step time p95 under 33 ms, population silent when idle, recruitment monotone *and* graded, `steer` correctly signed with no standing bias at symmetric drive, **DNp01 never spiking from optic-flow drive alone**, and the ESCAPE threshold not moving between zero and full drive. Also prints `DNG02_RECRUIT_SAT` and the recruitment curves as paste-ready lines — re-run and paste back after tuning `MAX_DRIVE_RATE` or the drive pool.

**Expected:** all checks pass, recruitment climbing smoothly from 0 to ~13 of 24 cells, ~18 ms/step.

### `test_optomotor_sign.py`: is the feedback loop the right way round?

Small and fast — run it after touching anything in the optomotor path. Drives the whole adapter chain with synthetic flow and asserts on the **commanded yaw**, the thing that actually reaches the motors.

```bash
python NeuralPathways/StabilizerNeuron/Tests/test_optomotor_sign.py      # normal env, brain runs as a subprocess
```

Exists because the DNg02 steering term uses the *opposite* sign convention to DNp06 two lines away in the same function (DNg02 tracks the contralateral wing; DNp06 steers away from looming). If that sign ever flips, the drone doesn't fly slightly worse — it yaws harder into its own drift until it hits something, and `test_dng02_circuit.py` can't catch it (it never sees a yaw command). Checks: drive mapping favours the right DNg02 for rightward motion; uncommanded rotation commands the opposite turn (negative feedback); contribution stays inside `DNG02_YAW_AUTHORITY`; a hard loom still yields `ESCAPE` with dodge yaw at exactly 0; `optomotor=False` ignores residual rotation entirely.

**Note:** with nothing moving, `steer` sits around +0.06 rather than 0 (residual population asymmetry, well under `OPTOMOTOR_STATE_THRESHOLD`, but watch for it on a first flight).

In the banana-eating drone brain, DNg02 runs as a yaw stabilizer in every state with `python Drone/tello_camera.py --stabilize` - see `../ScaredEating/README.md` for how it's mixed in (efference copy, gain) and `../ScaredEating/Tests/test_stabilizer_wiring.py` for its tests.

For the real-hardware flying versions of these checks — table-top perception (`tello_dng02_test.py`) and the first actual flying optomotor test (`tello_optomotor_flight_test.py`) — see `Drone/Tests/` and `Drone/README.md`.

## Notes

- `build_dng02_circuit.py` regenerates `dng02_circuit_neurons.json`. It downloads the FlyWire annotation table once and caches it at `../Data/flywire_neuron_annotations_630.tsv` (gitignored, 31 MB). Every selection rule is a constant at the top of the file, and it prints the resulting circuit so the output is self-checking.
- **The one modelling assumption in the DNg02 circuit, stated plainly:** DNg02 has essentially no visual input in this connectome — 137 of 12,848 incoming synapses come from visual projection neurons, none from the HS/VS wide-field tangential cells that carry optic flow, and none from the LC4/LPLC2 pool. Its input is central (posterior slope, inferior bridge, clamp, LAL, ascending from the VNC). Driving those central cells with optic flow is *stipulated*, not something the connectome supports — the pathway from wide-field motion to DNg02 is a published open question (Schnell, *Trends in Neurosciences* 2026). What *is* connectome-derived is everything downstream: which cell excites or inhibits which DNg02, how strongly, and therefore the recruitment order. That order is the scientifically interesting part — this is not "we found DNg02's visual pathway."
