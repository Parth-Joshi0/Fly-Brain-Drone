# NeuralPathways

The real Fly-Brain connectome, run live as the drone's autonomous controller. Two circuits share one Brian2 network:

- **Escape** (always on) — `EscapeNeuron/`'s looming detector feeds LC4/LPLC2 → DNp01/DNp03/DNp06, the Giant Fiber dodge. This is what makes the drone swat-reactive.
- **DNg02 flight-motor** (opt-in, `optomotor=True`) — a population of 24 descending neurons whose *recruitment count* sets thrust and steering from residual optic flow (`FoodNeuron/`'s sibling pathway for feeding is separate and doesn't touch this circuit).

Escape and DNg02 live in the same file pair because they share one Brian2 `Network`/`NeuronGroup`/`Synapses` — see `fly_brain_controller.py`'s docstring for why (a measured perf argument, not a shortcut), which is also why this couldn't be split into separate `EscapeNeuron/StabilizerNeuron` folders.

## Files

| File | What it does |
|---|---|
| `fly_brain_controller.py` | The actual Brian2 connectome: builds the LIF network from real FlyWire v630 synapses, runs it as a persistent subprocess (`conda run -n brian2`), and speaks stdin/stdout JSON lines. Never imported directly by `main.py`. |
| `flybrain_controller.py` | The adapter `main.py` actually imports (`FlyBrainController`). Same `decide(flow, state)` / `.state` / `.reset()` contract as `reflex_controller.py`, backed by `fly_brain_controller.py` over a subprocess so the main venv never needs Brian2 installed. |
| `build_dng02_circuit.py` | One-off generator for `dng02_circuit_neurons.json` — finds the 24 DNg02 cells and their 120-neuron drive pool from the connectome data in `Data/`. Run under the brian2 env; re-run and re-paste its output if `MAX_DRIVE_RATE` or the drive pool changes. |
| `dng02_circuit_neurons.json` | DNg02 flight-motor circuit: the 24 output neurons + drive pool, generated by `build_dng02_circuit.py`. |
| `looming_circuit_neurons.json` | The 274 neurons making up the LC4/LPLC2 → DNp01/DNp03/DNp06 escape circuit. |
| `DNG02_SESSION_NOTES.txt` | Handover notes from the session that built the DNg02 circuit — what was built, why, and what it measured. |
| `Data/` | The real FlyWire v630 connectome data the circuit is built from (rescued out of the upstream Fly-Brain clone, which is otherwise not vendored here — see the root README for credit). `2023_03_23_connectivity_630_final.parquet` and `...completeness_630_final.csv` are git-tracked; `flywire_neuron_annotations_630.tsv` is a gitignored 31 MB cache `build_dng02_circuit.py` downloads once. |

## Environments

Two Python environments are involved here:

| Environment | Needs | Used by |
|---|---|---|
| **brian2** (conda env) | `brian2`, `pandas`, `pyarrow` | `Tests/test_brain_circuit.py`, `Tests/test_dng02_circuit.py`, `build_dng02_circuit.py`, and the `fly_brain_controller.py` subprocess itself |
| everything else (e.g. `venv/`) | none of the above | `flybrain_controller.py` and its callers — the brain runs as a subprocess, so this side never links against Brian2 |

`flybrain_controller.py` finds the brian2 env on its own (common conda locations, or `conda run -n brian2`). If it can't, point `FLYBRAIN_PYTHON` at that env's python:

```bash
export FLYBRAIN_PYTHON=/path/to/envs/brian2/bin/python
```

## Tests (`Tests/`)

### `test_brain_circuit.py`: are the neurons firing?

Drives the LC4/LPLC2 → DNp01/DNp03/DNp06 circuit (`fly_brain_controller.py`) directly with fixed looming inputs, no simulator involved. Prints the synapse wiring into each output neuron, then for each stimulus (none, weak, strong, left-only, right-only): spike counts over 1 s, peak escape signal and whether it crosses the ESCAPE threshold (0.6), mean turn signal, and compute time per 20 ms brain step (must stay under ~33 ms for the 30 Hz control loop).

```bash
conda run -n brian2 python NeuralPathways/Tests/test_brain_circuit.py
```

**Expected:** silent with no stimulus. From loom ≈0.25 the Giant Fiber (DNp01) fires and ESCAPE = YES. Left-only loom → negative turn (turn right, away from it); right-only → positive.

### `test_dng02_circuit.py`: does the population code work?

The DNg02 counterpart to `test_brain_circuit.py`, and the **gate for everything downstream** — nothing DNg02-related should reach a real drone until this passes. Drives the flight-motor half directly and prints the recruitment ladder, cross-synapses back into the escape circuit, a symmetric drive sweep (recruited cells, `thrust`, `steer`), an asymmetric sweep, and a 2-D `loom × drive` sweep.

```bash
conda run -n brian2 python NeuralPathways/Tests/test_dng02_circuit.py
```

Ends in hard assertions and a non-zero exit on failure: step time p95 under 33 ms, population silent when idle, recruitment monotone *and* graded, `steer` correctly signed with no standing bias at symmetric drive, **DNp01 never spiking from optic-flow drive alone**, and the ESCAPE threshold not moving between zero and full drive. Also prints `DNG02_RECRUIT_SAT` and the recruitment curves as paste-ready lines — re-run and paste back after tuning `MAX_DRIVE_RATE` or the drive pool.

**Expected:** all checks pass, recruitment climbing smoothly from 0 to ~13 of 24 cells, ~18 ms/step.

### `test_optomotor_sign.py`: is the feedback loop the right way round?

Small and fast — run it after touching anything in the optomotor path. Drives the whole adapter chain with synthetic flow and asserts on the **commanded yaw**, the thing that actually reaches the motors.

```bash
python NeuralPathways/Tests/test_optomotor_sign.py      # normal env, brain runs as a subprocess
```

Exists because the DNg02 steering term uses the *opposite* sign convention to DNp06 two lines away in the same function (DNg02 tracks the contralateral wing; DNp06 steers away from looming). If that sign ever flips, the drone doesn't fly slightly worse — it yaws harder into its own drift until it hits something, and `test_dng02_circuit.py` can't catch it (it never sees a yaw command). Checks: drive mapping favours the right DNg02 for rightward motion; uncommanded rotation commands the opposite turn (negative feedback); contribution stays inside `DNG02_YAW_AUTHORITY`; a hard loom still yields `ESCAPE` with dodge yaw at exactly 0; `optomotor=False` ignores residual rotation entirely.

**Note:** with nothing moving, `steer` sits around +0.06 rather than 0 (residual population asymmetry, well under `OPTOMOTOR_STATE_THRESHOLD`, but watch for it on a first flight).

## Notes

- `build_dng02_circuit.py` regenerates `dng02_circuit_neurons.json`. It downloads the FlyWire annotation table once and caches it at `Data/flywire_neuron_annotations_630.tsv` (gitignored, 31 MB). Every selection rule is a constant at the top of the file, and it prints the resulting circuit so the output is self-checking.
- **The one modelling assumption in the DNg02 circuit, stated plainly:** DNg02 has essentially no visual input in this connectome — 137 of 12,848 incoming synapses come from visual projection neurons, none from the HS/VS wide-field tangential cells that carry optic flow, and none from the LC4/LPLC2 pool. Its input is central (posterior slope, inferior bridge, clamp, LAL, ascending from the VNC). Driving those central cells with optic flow is *stipulated*, not something the connectome supports — the pathway from wide-field motion to DNg02 is a published open question (Schnell, *Trends in Neurosciences* 2026). What *is* connectome-derived is everything downstream: which cell excites or inhibits which DNg02, how strongly, and therefore the recruitment order.
- `main.py` is deliberately **not** wired for optomotor yet — it builds its `flow` dict without `rotation`/`translation` keys, so `optomotor=True` there today would silently get a zero drive request.
- DNg02 steering uses the **opposite** sign convention to DNp06: DNg02 activity tracks wingbeat amplitude in the *contralateral* wing (more right-side DNg02 yaws right), whereas DNp06 steers *away* from looming. `flybrain_controller.py`'s `decide()` subtracts the DNg02 term where it adds the DNp06 one, two lines apart. Both are commented — don't "fix" either.
- The scripts that start the brain overwrite `flybrain_spikes.log` in the repo root, just as `main.py` does. It's gitignored.
